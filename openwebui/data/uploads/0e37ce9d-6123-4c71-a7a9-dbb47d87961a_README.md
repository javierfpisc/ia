# Publicación de materiales

Esta carpeta contiene la configuración de la fase de publicación. Ningún archivo de aquí publica nada por sí mismo: la publicación la realiza `scripts/publicar.py` y solo con autorización explícita del profesor.

## Archivos

| Archivo | Función | Lo mantiene |
|---|---|---|
| `repositorios.yml` | Destino de cada unidad: repositorio de GitHub, rama, rutas de `guia`, `introduccion`, `entorno`, directorios de conceptos y prácticas | Profesor |
| `mkdocs.yml` | Plantilla de MkDocs. El script rellena `site_name`, `site_description`, el enlace a GitHub y el `nav` a partir de los archivos publicados | Profesor (plantilla) |
| `repositorios.yml` → `rama` | Rama del repositorio de cada unidad donde se publica | Profesor |
| `repositorios.yml` → `mkdocs` | Ruta, dentro del repositorio de la unidad, donde se escribe el `mkdocs.yml` generado (p. ej. `mkdocs.yml` o `site/mkdocs.yml`) | Profesor |
| `instrucciones.txt` | Reglas de la publicación y restricciones obligatorias | Profesor |

Los datos de publicación no contienen credenciales. El acceso a GitHub es por SSH (`git@github.com:<organización>/<repositorio>.git`) con la clave SSH del sistema, que debe estar autorizada en la organización fuera del proyecto. Los repositorios de publicación deben ser privados; SSH no permite comprobarlo, así que el script lo recuerda en un aviso y el profesor debe verificarlo en GitHub.

## Qué se publica

- `contenidos/unidades/NN/*.md`: `guia`, `introduccion` y `entorno` van a sus rutas (`docs/1-guia.md`, `docs/2-introduccion.md`, `docs/3-entorno.md`); el resto, a `conceptos.directorio` (`docs/conceptos/`).
- `practicas/unidades/NN/*.md`: a `practicas.directorio` (`docs/practicas/`).
- `mkdocs.yml` generado en la ruta indicada por `mkdocs` del repositorio de la unidad.

Solo se tocan esas rutas. Cualquier otro cambio en el repositorio de destino detiene la publicación.

Las rutas `guia`, `introduccion`, `entorno`, `conceptos.directorio` y `practicas.directorio` deben estar dentro de la carpeta `docs/` que cuelga de la carpeta de `mkdocs` (MkDocs la usa como `docs_dir`). Por ejemplo, con `mkdocs: site/mkdocs.yml` las rutas deben empezar por `site/docs/`. Si no, la preparación falla. El `nav` se genera con rutas relativas a esa carpeta `docs/`.

## Procedimiento

1. **Preparar** (sin red ni Git; genera `trabajo/publicacion/NN/stage/`):

   ```bash
   python3 scripts/publicar.py 01 02
   python3 scripts/publicar.py todas
   ```

   Valida que existen las secciones declaradas, que hay Markdown en contenidos y prácticas, y busca credenciales en los archivos que se publicarían.

2. **Revisar** el resultado: lista de archivos y destinos, avisos y `stage/mkdocs.yml`.

3. **Publicar** solo con autorización explícita del profesor:

   ```bash
   python3 scripts/publicar.py 01 --publicar
   ```

   Comprueba por SSH (`git ls-remote`) que la rama existe y que hay acceso. Clona la rama en `trabajo/publicacion/NN/clon/`, sustituye los Markdown gestionados, hace commit y push. Si el repositorio, la rama o el contenido no son los esperados, no confirma nada y muestra el motivo.

Opciones: `--rama NOMBRE` (si `repositorios.yml` no define `rama`) y `--origen RUTA` (repositorio local, solo para pruebas).

## Requisitos previos de `repositorios.yml`

- `rama` y `mkdocs` son obligatorias para cada unidad. Si falta `rama`, `--publicar` no se ejecuta salvo que se indique `--rama`. Si falta `mkdocs`, la preparación falla.
- La unidad 00 no está declarada; el script avisa de que no se publica.

## Limitaciones conocidas

- La plantilla `mkdocs.yml` referencia `stylesheets/extra.css`. El script no publica esa hoja de estilos, por lo que hay que añadirla al repositorio de destino o retirar la referencia.
- Un archivo con credenciales en claro (por ejemplo, contraseñas de laboratorio en una práctica) bloquea la publicación de esa unidad hasta que el profesor lo corrija.
- Las pruebas de publicación se han hecho contra un repositorio local de prueba; no se ha publicado en GitHub.
