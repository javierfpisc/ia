# Gestión por Línea de Comandos en Proxmox VE

## Introducción: ¿Por qué usar la CLI?
Aunque Proxmox ofrece una interfaz web (GUI) intuitiva, la **CLI** permite a los administradores realizar tareas con mayor velocidad, acceder a opciones de depuración profunda y, lo más importante, sentar las bases para la **automatización** mediante scripts y herramientas como Ansible. 

En Proxmox, casi todas las herramientas de usuario son "wrappers" que interactúan directamente con la **API RESTful** del sistema.

---

## Gestión de Máquinas Virtuales y Contenedores
Las dos herramientas principales que todo administrador debe dominar son `qm` y `pct`.

### QEMU/KVM Virtual Machines (`qm`)
Se utiliza para gestionar máquinas virtuales completas.

*   **Listar VMs en el nodo:** `qm list`.
*   **Control de estado:**
    *   `qm start <vmid>`: Inicia la máquina.
    *   `qm shutdown <vmid>`: Apagado ordenado vía ACPI o Guest Agent.
    *   `qm stop <vmid>`: Apagado forzado (equivalente a tirar del cable).
    *   `qm reboot <vmid>`: Reiniciar VM
*   **Configuración y Recursos:**
    *   Ver configuración actual (incluyendo cambios pendientes): `qm config <vmid>`.
    *   Añadir espacio a un disco (ej. +5G al disco scsi0): `qm disk resize <vmid> scsi0 +5G`.
    *   Mover un disco a otro almacenamiento y borrar el origen: `qm disk move <vmid> scsi0 <storage_target> --delete 1`.
*   **Creación y Clonación:**
    *   `qm clone <vmid> <newid> --name <nombre>`: Crea una copia de una VM.
    *   `qm template <vmid>`: Convierte una VM en una plantilla de solo lectura.

### Linux Containers (`pct`)
Herramienta para la gestión de contenedores ligeros (LXC).

*   **Entrar directamente al shell del contenedor:** `pct enter <vmid>`.
*   **Ejecutar un comando desde el host:** `pct exec <vmid> -- <comando>`.
*   **Ver uso de disco interno:** `pct df <vmid>`.

## Gestión de Almacenamiento y Ceph
La flexibilidad de Proxmox reside en su capacidad de gestionar múltiples backends de almacenamiento.

### Proxmox VE Storage Manager (`pvesm`)
Permite administrar pools de almacenamiento y volúmenes de disco.

*   **Estado de todos los almacenamientos:** `pvesm status`.
*   **Escanear recursos externos (ej. NFS):** `pvesm scan nfs <IP_del_servidor>`.
*   **Listar contenido (ISOs, Backups, Discos):** `pvesm list <ID_storage>`.

### Rendimiento (Benchmarking):
Realizar un test rápido de rendimiento de CPU y latencia de disco: `pveperf`

### Gestión de Ceph (`pveceph`)
Para entornos hiperconvergentes, Proxmox integra la gestión de clústeres Ceph.

*   **Ver estado de salud del clúster Ceph:** `pveceph status`.
*   **Crear un nuevo OSD (Disco de almacenamiento):** `pveceph osd create /dev/sdX`.

## Gestión del Nodo y Servicios del Sistema
Para asegurar la estabilidad del servidor, es vital monitorear los procesos propios de Proxmox.

### Node Management (`pvenode`). Obtención de Información y Diagnóstico de Problemas

*   **Historial y Logs de Tareas:**
    *   Ver las últimas 50 tareas realizadas en el nodo: `pvenode task list`.
    *   Filtrar tareas fallidas de una VM específica: `pvenode task list --errors --vmid <vmid>`.
    *   Ver el log detallado de una tarea específica (usando su UPID): `pvenode task log <upid>`.
*   **Diagnóstico de servicios del sistema (Stack Proxmox):**
    *   Comprobar estado de los demonios críticos: `systemctl status pve-cluster pvedaemon pvestatd pveproxy`.
    *   Si la gestión web no responde, secuencia de reinicio recomendada: 
      `service pve-cluster restart && service pvedaemon restart && service pvestatd restart && service pveproxy restart`.
    *   Ver logs en tiempo real del sistema de archivos del clúster: `journalctl -u pve-cluster -f`.

### Demonios de Servicio Críticos
Si la interfaz web no responde pero el SSH funciona, verifique estos servicios con `systemctl`:

*   `pve-cluster`: El motor del sistema de archivos distribuido (**pmxcfs**).
*   `pvedaemon`: Procesa las peticiones locales de la API.
*   `pveproxy`: El servidor web que expone la interfaz en el puerto 8006.
*   `pvestatd`: Recolecta estadísticas de rendimiento.

### Gestión y Diagnóstico del Clúster (`pvecm`)

*   **Estado de salud del clúster:**
    *   Ver estado general, quórum y versión de configuración: `pvecm status`.
    *   Listar nodos activos y sus IDs en el clúster: `pvecm nodes`.
*   **Recuperación de Quórum:**
    *   **Emergencia:** Forzar al nodo actual a tener quórum (útil si fallan varios nodos y el clúster se bloquea en modo solo lectura): `pvecm expected 1`.
*   **Sincronización:**
    *   Actualizar certificados y huellas SSH en todos los nodos: `pvecm updatecerts`.

## El Puente hacia la Automatización: `pvesh`
La herramienta `pvesh` es la interfaz de línea de comandos para la **API de Proxmox VE**. Es el paso previo a escribir scripts complejos o usar Ansible.

*   Permite navegar por la API como si fuera un sistema de archivos:
    ```bash
    pvesh get /nodes            # Lista los nodos del clúster
    pvesh get /nodes/pve1/qemu  # Lista todas las VMs del nodo pve1
    pvesh create /nodes/pve1/network --iface vmbr0 \
    --type bridge ... # Configura red vía API
    pvesh get /cluster/resources # Estado de los recursos
    ```

### Evolución a Ansible y Scripts
Otros aspectos relacionadas con el acceso y gestión del API, además del ya descrito `pvesh` serían:

1.  **Scripts en Python:** Usar librerías para interactuar con los mismos endpoints de la API.
2.  **Tokens de API:** Crear credenciales seguras con `pveum user token add` para que los scripts no usen la contraseña de root.
3.  **Ansible:** Utilizar los módulos de Proxmox que, internamente, ejecutan estos mismos comandos y llamadas a la API para garantizar el estado deseado de la infraestructura.

---
**Tip de Diagnóstico:** Si notas que los comandos de Proxmox (`qm`, `pvesm`) tardan mucho en responder, es probable que haya un problema con el quórum del clúster o con un montaje NFS inalcanzable. Usa `pvecm status` para verificar el quórum.
