# Práctica: Alta Disponibilidad y Afinidad en Proxmox VE

## Crear Recurso de HA (MV)

Disponemos de un recurso (MV), vamos a utilizar esa MV para establecer políticas relacionadas con la gestión de la Alta Disponibilida (HA)

Añadiremos la Máquina Virtual (MV) seleccionada al sistema de Alta Disponibilidad (HA) para que sea gestionada por el clúster. Para ello podemos actuar desde la interfaz web de Proxmox (sección HA), o bien desde la línea de comandos. Supongamos que la MV tiene como ID 100, procederíamos con el comando:
```bash
ha-manager add vm:100 --state started
```

- vm:100 → identifica el recurso (tipo y ID).
- --state started → indica que quieres que la VM esté en estado arrancado bajo gestión HA.

!!!important "IMPORTANTE"
    El definir el estado (--state) influye en como la MV se mantendrá en el cluster.
    En este caso siempre estará iniciada según las políticas de HA definidas.

Opcionalmente puedes especificar parámetros avanzados:

- --group <grupo> → para asignarla a un grupo HA específico.
- --max_relocate <n> → número máximo de reintentos de migración si falla.
- --max_restart <n> → máximo de reintentos de arranque después de fallo.


## Afinidad de Nodo (HA Node Affinity Rules)
La **afinidad de nodo** permite indicar al sistema en qué nodos puede o debería ejecutarse una MV. Esto establece prioridades de ejecución, aunque no siempre de forma rígida. Por simplicidad ejecutaremos los pasos siguientes desde la interfaz web de Proxmox **HA->Affinity Rules**.

* **Prueba de conmutación básica**
    * Crear una regla de afinidad que asigne el recurso (MV) al nodo `pve2`.
    * **Prueba de fallo:** Apagar el nodo `pve2`. La MV debería levantarse automáticamente en otro nodo del clúster.
    * **Prueba de retorno:** Volver a arrancar `pve2`. La MV debería migrar de vuelta al nodo original.
 
**Nota:** Si se define una **afinidad estricta** en un solo nodo, la MV no se migrará a otro host aunque el nodo principal falle.

* **Configuración de prioridades múltiples**
    * Definir un grupo HA asignando las siguientes prioridades a los nodos:
        * `pve1`: prioridad 10.
        * `pve2`: prioridad 20.
        * `pve3`: prioridad 30.
    * **Comportamiento esperado:** Proxmox intentará ejecutar la VM en el nodo con mayor prioridad (`pve3`). Si no está disponible, usará el siguiente en la escala. Si el nodo de mayor prioridad vuelve a estar en línea, la VM migrará de vuelta a éste.

* **Supervisión y verificación manual**
    * Para ver el estado actual del sistema de HA, ejecutar en la consola:
        ```bash
        ha-manager status
        ```
    * **Prueba de migración manual:** Intentar mover la MV a un nodo de menor prioridad. Se debe observar que el recurso vuelve al nodo de mayor prioridad inmediatamente después de terminar la migración si este sigue disponible.

## Afinidad de Recurso  (HA Resource Affinity Rules)
Esta regla define si dos o más recursos deben ejecutarse "juntos o separados" entre sí.

* **Preparación**
    * Desactivar las reglas de afinidad de nodo configuradas en el paso anterior.
    * Clonar la MV de prueba (Debian) para disponer de un segundo recurso en el clúster.

**Nota**: Si un recurso ya está bajo una regla de afinidad de nodo, no podrá utilizarse en una regla de afinidad de recurso.

* **Regla "Keep Separate" (Antiafinidad)**
    * Definir una regla de HA de afinidad de recurso indicando que las dos MVs se mantengan **separadas**.
    * Verificar que el sistema sitúa cada MV en un nodo distinto.

* **Regla "Keep Together" (Afinidad)**
    * Modificar la regla anterior para que los recursos se mantengan **juntos**.
    * Verificar cómo una de las MVs migra automáticamente para reunirse con la otra en el mismo nodo físico.

## Verificación de HA General
* **Comprobación final:** Validar que en Proxmox VE la Alta Disponibilidad funciona correctamente incluso sin reglas de afinidad definidas, siempre que el recurso haya sido añadido previamente al sistema de HA.
