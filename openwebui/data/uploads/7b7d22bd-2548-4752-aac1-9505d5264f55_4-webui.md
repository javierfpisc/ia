# Administración de Proxmox VE desde la Web UI
Para un perfil técnico de administración de sistemas la administración más efectiva y funcional es la consola Linux y todo el conjunto de herramientas CLI vinculadas a Proxmox. Sin embargo, ciertos aspectos de gestión de **Proxmox VE 9.x** se pueden gestionar y visualizar cómodamente desde la interfaz Web de gestión. De un modo gráfico esta interfaz basa en comprender la jerarquía del **Proxmox Cluster File System (pmxcfs)**, el cual replica la configuración en `/etc/pve/` a través de todos los nodos usando **Corosync**.

A continuación, se detallan las bases:

## Nivel Datacenter: Orquestación Global
Es el nivel jerárquico superior donde se definen políticas que afectan a todo el clúster.

*   **Gestión de Almacenamiento (`Datacenter > Storage`):** Aquí se configuran los backends de almacenamiento. Proxmox distingue entre **almacenamiento a nivel de fichero** (NFS, CIFS) para ISOs y backups, y **almacenamiento a nivel de bloque** (ZFS, Ceph/RBD, LVM-Thin) para discos de alto rendimiento. La configuración reside en `/etc/pve/storage.cfg`.
*   **Alta Disponibilidad (HA) (`Datacenter > HA`):** Se gestionan los recursos mediante identificadores únicos (**SID**), como `vm:100`. En la versión 9.x, los antiguos "grupos" han evolucionado hacia **Reglas de Afinidad de Nodo**, permitiendo definir de forma granular dónde debe ejecutarse un recurso bajo condiciones de fallo.
*   **Seguridad y RBAC (`Datacenter > Permissions`):** Gestión de **Realms** (dominios de autenticación como LDAP, AD o el servidor interno de Proxmox) y **API Tokens**. Los tokens son vitales para la automatización, ya que permiten acceso *stateless* sin usar contraseñas interactivas.

## Nivel Nodo: Administración del Host (Bare Metal)
Representa la gestión del sistema operativo base de cada nodo y el hardware físico.

*   **Subsistema de Discos (`Nodo > Disks`):** Permite la administración de **LVM**, **LVM-Thin** y **ZFS**. Para ZFS, Proxmox facilita la creación de pools (mirrors, RAIDZ) con protección nativa contra la corrupción de datos y soporte de **Snapshots** casi instantáneos.
*   **Mantenimiento y Repositorios (`Nodo > Updates`):** Gestión de las fuentes de software (`/etc/apt/sources.list.d/`). Es crítico configurar correctamente el repositorio **pve-no-subscription** para entornos de laboratorio o **pve-enterprise** para producción.
*   **Consola de Bajo Nivel:** Acceso a la **Shell** del host para tareas que el GUI no cubre, como el uso de `smartctl` para monitorizar la salud de los discos físicos.

## Gestión de Sistemas Guest: VMs (KVM) y Contenedores (LXC)
Proxmox utiliza una tecnología dual para optimizar las cargas de trabajo.

*   **Máquinas Virtuales (KVM):** Se gestionan mediante el comando `qm`. Aspectos clave:
    *   **CPU:** Selección del tipo de CPU (p.ej., `host` para máximo rendimiento o modelos específicos para compatibilidad en migraciones).
    *   **Memoria:** Configuración de **Ballooning** para compartir RAM dinámicamente entre el host y los invitados.
    *   **Cloud-Init:** Interfaz para inyectar configuraciones (IPs, usuarios, claves SSH) en el primer arranque, esencial para despliegues masivos.
*   **Contenedores (LXC):** Gestión mediante `pct`. Son ideales para servicios ligeros de Linux ya que comparten el kernel del host, reduciendo el *overhead*. Se recomienda el uso de **contenedores sin privilegios** (unprivileged) para mayor seguridad.

## Almacenamiento Distribuido: Ceph (HCI)
Para infraestructuras hiperconvergentes, Proxmox integra la gestión de **Ceph** directamente en la interfaz.

*   **Componentes de Red:** Requiere definir una red pública y una de clúster (preferiblemente separadas físicamente).
*   **Servicios:** Desde `Nodo > Ceph`, se despliegan los **Monitores (MON)**, los **Gestores (MGR)** y los **OSD** (discos físicos de almacenamiento).
*   **Pools y FS:** Creación de pools de bloques (**RBD**) para discos de VMs o **CephFS** para un sistema de archivos distribuido común a todos los nodos.

## Redes Físicas y SDN

*   **Configuración Estándar (`Nodo > Network`):** Gestión de **Linux Bridges** (`vmbr0`), **Bonding** (LACP para redundancia) y **VLANs**. Los cambios se aplican al archivo `/etc/network/interfaces`.
*   **Redes Definidas por Software (SDN):** Proporciona una capa de abstracción para crear **VNets** y **Zonas** (como VXLAN o EVPN), permitiendo redes virtuales aisladas que pueden extenderse a través de múltiples nodos del clúster sin configurar switches físicos de forma manual.

## Resumen de Archivos Críticos y Comandos CLI
Como hemos mencionado, la interfaz Web nos permite una visualización agradable y cómoda de aspectos importantes del clúster. Sin embargo para un administrador, el control real está en la correlación entre el archivo de texto y la herramienta. Por tanto siempre necesitaremos tener a mano las herramientas CLI necesarias. A continuación vemos las correspondencias más importantes al respecto:

| Ámbito | Herramienta | Archivo de Configuración en `/etc/pve/` |
| :--- | :--- | :--- |
| **VMs KVM** | `qm` | `qemu-server/<VMID>.conf` |
| **Contenedores** | `pct` | `lxc/<CTID>.conf` |
| **Almacenamiento** | `pvesm` | `storage.cfg` |
| **Clúster** | `pvecm` | `corosync.conf` |
| **Ceph** | `pveceph` | `ceph.conf` |
| **Usuarios** | `pveum` | `user.cfg` y `priv/shadow.cfg` |
| **API Shell** | `pvesh` | N/A (Interactúa con todos los *endpoints*) |
