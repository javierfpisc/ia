# Seguridad en Proxmox VE. Enfoque RBAC

El modelo de seguridad de **Proxmox VE** se fundamenta en un sistema de **Control de Acceso Basado en Roles (RBAC)** altamente granular y jerárquico. Para un administrador de sistemas, la clave de este modelo reside en entender que la seguridad no se aplica directamente sobre los objetos, sino a través de una "triangulación" de conceptos que se orquestan mediante reglas de **ACL (Access Control Lists)**.

A continuación, se describen los pilares que componen este ecosistema y cómo interactúan entre sí:

### 1. Sujetos: Usuarios y Grupos
La identidad en Proxmox se gestiona a través de:

*   **Usuarios:**, los cuales siempre están vinculados a un **Realm** (ámbito de autenticación), como `pve` (autenticación local de Proxmox) o `pam` (usuarios del sistema operativo).
*   **Grupos:** Funcionan como contenedores de usuarios para simplificar la gestión masiva. En entornos técnicos, la recomendación es asignar permisos a los grupos y no a individuos, facilitando la escalabilidad de la política de seguridad.

### 2. Objetos y Rutas (Paths / Scope)
La seguridad en Proxmox es **jerárquica**. Cada recurso (máquinas virtuales, contenedores, almacenamiento, pools) tiene una **Ruta** de acceso única que define su posición en el árbol de recursos del clúster.

*   La raíz se representa con `/` (todo el clúster).
*   Se pueden definir rutas específicas como `/pool/LAB` o `/vms/100` para limitar el **Scope** (alcance) de un permiso.

### 3. Roles y Privilegios
Un **Rol** es simplemente un conjunto de **Privilegios** (permisos técnicos de bajo nivel como `VM.PowerMgmt` o `Datastore.Audit`).

*   Proxmox ofrece roles predefinidos (como `Administrator` o `PVEAuditor`), pero permite la creación de **Roles Personalizados** para ajustar las capacidades de un usuario a sus tareas reales, cumpliendo así el **principio de mínimo privilegio**.

### 4. La Conexión: Permisos ACL
La **ACL** es el pegamento que une los conceptos anteriores. Una regla de acceso se define siempre bajo la fórmula:
> **ACL = (Usuario/Grupo) + (Ruta) + (Rol)**

Al aplicar esta fórmula, el sistema otorga a un sujeto específico un conjunto de capacidades sobre un recurso o grupo de recursos delimitado por la ruta.

### Mecánica de funcionamiento (Reglas de Oro)
Para administrar con éxito la seguridad en Proxmox 9.1.6, deben tenerse en cuenta estas dos reglas críticas de comportamiento del motor de seguridad:

*   **Acumulación de Permisos:** El sistema es **puramente aditivo**. Si un usuario recibe permisos a través de su cuenta individual y también a través de varios grupos, Proxmox **suma** todos los privilegios resultantes.
*   **Inexistencia de "Deny":** A diferencia de otros sistemas de archivos o directorios activos, en Proxmox **no existe el permiso de denegación explícita**. Si un usuario no tiene un permiso asignado en una ruta específica (ni por grupo ni de forma directa), simplemente no tiene acceso. La restricción de acceso se logra controlando cuidadosamente el **Scope** (la ruta) de las ACLs.

Este marco conceptual permite que, mediante herramientas como `pveum` o la interfaz web, el administrador pueda simular con precisión escenarios reales de operación, auditoría y administración total dentro del clúster.
