# Configuración de acceso de usuario operador en k3s

## Configurar kubeconfig, si no está definido

```bash
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown ${USER}:${USER} ~/.kube/config
export KUBECONFIG=~/.kube/config
```

Para hacerlo persistente:

```bash
echo 'export KUBECONFIG=$HOME/.kube/config' >> ~/.bashrc
```

## Definir credenciales y contexto

A continuación vamos a crear los elementos de autenticación, mediante certificado, para el usuario `operador` que vamos a crear. Usaremos `openssl` para generar la clave privada, la solicitud de firma (CSR) y finalmente el certificado (CRT).

```bash
openssl genrsa -out operador.key 2048
openssl req -new -key operador.key -out operador.csr -subj "/CN=operador"
sudo openssl x509 -req \
  -in operador.csr \
  -CA /var/lib/rancher/k3s/server/tls/client-ca.crt \
  -CAkey /var/lib/rancher/k3s/server/tls/client-ca.key \
  -CAcreateserial \
  -out operador.crt \
  -days 365
```
Establecemos las credenciales para el usuario y definimos el contexto de kubectl:
```bash
kubectl config set-credentials operador \
  --client-certificate=operador.crt \
  --client-key=operador.key
kubectl config set-context operador-context --cluster=default --user=operador
```

## Cambiar contexto de kubectl

Pasamos a operar con `kubectl` desde el nuevo contexto creado, y por tanto con las restricciones correspondientes:
```bash
kubectl config use-context operador-context
```

### Intentar recuperar pods del namespace kube-system

Si a continuación ejecutamos:
```bash
kubectl get -n kube-system pods
```
**Resultado esperado:** `error: You must be logged in to the server (Unauthorized)`. El motivo es la falta de permisos para el usuario asociado al contexto.

## Crear Role y RoleBinding para el usuario operador

Volvemos al contexto por defecto:

```bash
kubectl config use-context default
```
A continuación vamos a definir los elementos necesarios de Kubernetes, **Role y RoleBinding**, que permitirán otorgar permisos sobre el contexto asociado al usuario **operador**.

Creamos archivo `rbac-operador.yaml`:
```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: kube-system
  name: lector-pods-sistema
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: acceso-operador
  namespace: kube-system
subjects:
- kind: User
  name: operador
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: lector-pods-sistema
  apiGroup: rbac.authorization.k8s.io
```

Aplicamos los artefactos del archivo:

```bash
kubectl apply -f rbac-operador.yaml
```

### Verificar funcionamiento

Volvemos a cambiar el contexto:
```bash
kubectl config use-context operador-context
```
El comando ahora sí debería funcionar:
```bash
kubectl get -n kube-system pods
```

## Alternativa: Usar ServiceAccount

```bash
kubectl create serviceaccount operadorsa -n kube-system
kubectl create rolebinding operador-sa-binding \
  --role=lector-pods-sistema \
  --serviceaccount=kube-system:operadorsa \
  -n kube-system
kubectl config set-context operadorsa-context \
  --cluster=default \
  --user=operadorsa \
  --namespace=kube-system
```

Obtener el token:

```bash
kubectl -n kube-system create token operadorsa
```

Editar `~/.kube/config` y añadir la configuración correspondiente.

```
- name: operadorsa
  user:
    token: TOKEN_OBTENIDO_ANTERIORMENTE
```

## Un poco de automatización

Usaremos ahora unos scripts que permiten automatizar parte del proceso anterior. Tenemos:

* **crear-usuario.sh**: Crea las credenciales para un usuario, y define un contexto asociado dentro de un namespace
* **asignar-role.sh**: Crea el RoleBinding para asociar al contexto del usuario el Role indicado en el correspondiente namespace

Desde el directorio vagrant transferimos los scripts al nodo manager:
```bash
vagrant ssh kuber1 -c "cat > /tmp/crear-usuario.sh" < crear-usuario.sh
vagrant ssh kuber1 -c "chmod a+x /tmp/crear-usuario.sh"
vagrant ssh kuber1 -c "cat > /tmp/asignar-role.sh" < asignar-role.sh
vagrant ssh kuber1 -c "chmod a+x /tmp/asignar-role.sh"
```
Accedemos al nodo `kuber1` y ejecutamos desde el context **default**, para tener permisos necesarios, (`kubectl config use-context default`):
```bash
/tmp/crear-usuario operador2 kube-system
/tmp/asignar-role operador2 kube-system lector-pods-sistema
```
Comprobamos que se ha aplicado correctamente el contexto y el role asociado:
```bash
kubectl config use-context operador2-context
kubectl get pods -n kube-system
```
