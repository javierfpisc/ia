# Guía docente de la unidad

## 1. Contextualización

Esta unidad aborda las interfaces y herramientas para administrar y automatizar infraestructura con **Proxmox VE**. Se pasa de la gestión visual desde la Web UI a la línea de comandos y, finalmente, a la API REST y a herramientas de automatización con Python y Bruno.

El entorno de referencia está formado por tres nodos Proxmox virtualizados en VirtualBox y gestionados con Vagrant, según los recursos de la unidad anterior.

La secuencia didáctica progresa desde la comprensión del entorno y sus interfaces hasta la ejecución de operaciones repetibles y la resolución de un ejercicio de automatización. Las actividades prácticas deben realizarse en el laboratorio autorizado, verificando antes de cada operación el nodo, el identificador del recurso y el efecto esperado. Las acciones de parada o eliminación se aplicarán únicamente a los recursos creados para las prácticas.

- **Periodo lectivo:** del 23 de noviembre al 17 de diciembre de 2026.

## 3. Objetivos de aprendizaje

Al finalizar la unidad, el alumnado deberás:

1. Explicar el papel de la Web UI, la CLI y la API REST en la administración de Proxmox VE, y elegir una interfaz adecuada para una tarea.
2. Consultar el estado de un clúster y administrar máquinas virtuales, almacenamiento y recursos mediante comandos apropiados, verificando los resultados.
3. Diferenciar autenticación interactiva mediante ticket y autenticación automatizada mediante token, y aplicar el principio de privilegio mínimo en el diseño de credenciales.
4. Interpretar rutas, métodos HTTP, respuestas JSON y los identificadores de tareas asíncronas (UPID) de la API.
5. Preparar una plantilla con Cloud-Init y comprender cómo se personalizan clones mediante parámetros de usuario, claves SSH y red.
6. Ejecutar y explicar un flujo automatizado de despliegue, comprobación, encendido, parada y limpieza mediante Python o Bruno.
7. Organizar una colección de peticiones o un script de forma reproducible, controlar los parámetros de entrada y documentar las comprobaciones realizadas.

## 4. Desarrollo conceptual

### 4.1. Entorno y modelo de gestión

La unidad comienza con el clúster de laboratorio y su organización. Se estudian los niveles de administración desde la Web UI —centro de datos, nodo y recursos invitados— y la relación entre la configuración distribuida y los comandos que actúan sobre ella. La interfaz gráfica proporciona visibilidad y gestión interactiva; la CLI favorece la precisión y el diagnóstico; la API permite integrar operaciones en programas y herramientas externas.

### 4.2. CLI y ciclo de vida de los recursos

Se identifican las herramientas habituales: `qm` para máquinas virtuales KVM, `pct` para contenedores LXC, `pvesm` para almacenamiento, `pvecm` para el clúster y `pvesh` para invocar la API desde la línea de comandos. Se practican la consulta de estado y configuración, las operaciones de inicio y parada, la clonación y, cuando corresponda al entorno, la inspección de almacenamiento y tareas.

La selección del comando debe atender a su impacto: por ejemplo, `qm shutdown` solicita un apagado ordenado, mientras que `qm stop` fuerza la parada. Antes de ejecutar cambios, se comprueban la identidad del recurso y el estado del clúster.

### 4.3. API REST y autenticación

La API organiza los recursos mediante rutas, utiliza métodos HTTP para consultar o cambiar su estado y, habitualmente, intercambia datos JSON. Algunas operaciones son asíncronas: devuelven un UPID que hay que consultar hasta confirmar el resultado.

Se estudian los tickets de sesión, destinados principalmente a interacciones de usuario, y los tokens API, adecuados para automatización. La gestión de usuarios, realms, permisos RBAC y separación de privilegios sirve para comprender que una credencial de automatización debe tener únicamente los permisos necesarios. El secreto de un token debe protegerse y no incluirse en repositorios ni compartirse.

### 4.4. Cloud-Init y plantillas

Cloud-Init configura una máquina virtual en su primer arranque a partir de parámetros suministrados por Proxmox. Se revisa el flujo de preparación de una imagen, incorporación del dispositivo Cloud-Init, configuración de arranque y conversión a plantilla. A partir de ella se pueden clonar instancias con identidad, claves y configuración de red propias.

### 4.5. Automatización con Python y Bruno

La práctica de Python utiliza `proxmoxer`, un archivo YAML de configuración y operaciones de clonación, configuración, arranque y eliminación. Se revisan el tratamiento de tareas asíncronas y la configuración de Cloud-Init. Los scripts auxiliares permiten ejecutar tareas de administración remota sobre las instancias.

Bruno organiza peticiones HTTP en archivos de texto versionables. Las colecciones de creación, estado, arranque, parada y eliminación permiten entender el intercambio con la API y reutilizar variables de entorno. Como una petición Bruno representa una llamada HTTP individual, el ejercicio propone complementar la colección con scripts Bash para iterar sobre varias instancias y reutilizar acciones de gestión.

## 5. Desarrollo práctico

La secuencia de trabajo recomendada es:

1. **Reconocimiento del laboratorio:** identificar nodos, recursos y herramientas disponibles; consultar el estado antes de operar.
2. **Exploración desde CLI:** obtener información del clúster y de las máquinas virtuales, revisar configuración y practicar el ciclo de vida sobre recursos de laboratorio.
3. **Autenticación:** comprender tickets y crear/usar un token siguiendo las instrucciones de la práctica. No reutilizar ni publicar secretos reales.
4. **Plantilla Cloud-Init:** preparar o inspeccionar la plantilla de referencia y verificar qué valores se inyectan en los clones.
5. **Automatización con Python:** preparar el entorno virtual, revisar la configuración, desplegar las instancias descritas y comprobar la ejecución; realizar la limpieza prevista.
6. **Automatización con Bruno:** ejecutar las peticiones de forma ordenada y confirmar las respuestas. Completar el trabajo con `create.sh` para crear varias instancias y un script de gestión para consultar estado, arrancar, parar y borrar.
7. **Verificación y cierre:** contrastar el resultado en Proxmox y mediante las herramientas usadas, registrar incidencias y eliminar únicamente los recursos de práctica.

Las instrucciones detalladas y los artefactos se encuentran en [entorno](./entorno.md), [CLI Deploy](./practicas/cli-deploy.md), [Autenticación](./practicas/autenticacion.md), [Python-Deploy](./practicas/python-deploy.md), [Bruno-Deploy](./practicas/bruno-deploy.md) y [Despliegue con Bruno](./ejercicios/bruno-tarea.md).

| Tramo | Trabajo principal | Evidencia de aprendizaje |
|---|---|---|
| Semana 1 | Revisar el entorno, la jerarquía de gestión y la Web UI; familiarizarse con el clúster y sus recursos. | Esquema de las interfaces y comprobaciones iniciales del laboratorio. |
| Semana 2 | Practicar CLI y ciclo de vida de VMs; estudiar autenticación, roles y API REST. | Registro de comandos ejecutados, resultados y explicación de ticket, token y UPID. |
| Semana 3 | Estudiar Cloud-Init y la plantilla; preparar el entorno Python y ejecutar el despliegue de prueba. | Instancias configuradas y evidencia de las fases de clonación, configuración y arranque. |
| Semana 4 (hasta el 17 de diciembre) | Trabajar con las colecciones Bruno y completar el ejercicio de scripts Bash; comprobar y limpiar el laboratorio. | `create.sh`, script de gestión, resultados de pruebas y breve explicación de decisiones. |

Al comienzo de cada sesión, conviene revisar qué recursos se crearon en la sesión anterior. Al final, se recomienda registrar los comandos y parámetros relevantes, el resultado observado y cualquier tarea pendiente. El alumnado debe avanzar desde la consulta no destructiva hacia las operaciones de cambio y eliminación, que requieren una comprobación previa explícita.
