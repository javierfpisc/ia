# Cloud-Init en Proxmox VE: Despliegue Automatizado
A continuación se explica el uso de **Cloud-Init** en Proxmox VE, una herramienta fundamental para automatizar el despliegue de infraestructura y permitir la inicialización rápida de máquinas virtuales (VM) sin intervención manual. Actúa como un puente entre la infraestructura (Proxmox) y el sistema operativo invitado, permitiendo que la máquina se configure a sí misma de forma automática durante su primer arranque.

## ¿Cómo funciona en Proxmox?
A diferencia de otros entornos donde la configuración se pasa por red, Proxmox VE utiliza un método basado en hardware virtual:

*  **Generación de Datos:** Proxmox toma los ajustes definidos por el administrador (IPs, usuarios, etc.) y genera una **imagen ISO especial**.
*  **Entrega:** Esta ISO se conecta a la máquina virtual como una unidad de CD-ROM virtual.
*  **Ejecución:** Al arrancar, el software Cloud-Init dentro de la VM detecta esta unidad, lee los archivos de configuración y aplica los cambios al sistema.

## Concepto y Objetivos
**Cloud-Init** es el paquete estándar para la inicialización temprana de instancias de máquinas virtuales en diversas distribuciones de Linux. 

### Objetivos Principales:

*   **Automatización:** Configurar el sistema operativo (red, usuarios, claves) automáticamente en el primer arranque.
*   **Idempotencia:** Asegurar que las máquinas desplegadas a partir de una misma base tengan identidades únicas (nombres de host, claves SSH, etc.).
*   **Velocidad:** Reducir drásticamente el tiempo de despliegue masivo mediante el uso de plantillas y clones enlazados.
*   **Personalización Individual:** A partir de un único **Template**, se pueden crear cientos de clones, cada uno con su propio nombre de host, dirección IP y credenciales de acceso.
*   **Estandarización:** Asegura que todas las máquinas sigan el mismo patrón de configuración, reduciendo errores humanos.

## Imágenes Cloud-Init: Cómo Obtenerlas
Existen dos formas principales de trabajar con estas imágenes:

1.  **Imágenes listas para usar (Cloud Images):** La mayoría de las distribuciones (Ubuntu, Debian, CentOS) ofrecen archivos `.qcow2` ya preparados para entornos de nube (como OpenStack), que funcionan perfectamente en Proxmox.
2.  **Preparación manual:** Se puede instalar el paquete `cloud-init` dentro de cualquier VM estándar de Proxmox:
    ```bash
    # Ejecutado dentro de la VM (ej. Debian/Ubuntu)
    apt-get install cloud-init
    ```
    *Nota: Se recomienda preparar las imágenes uno mismo para saber exactamente qué software contienen.*

## Creación de una Plantilla de Referencia (Template)
Para que el despliegue masivo sea efectivo, es necesario establecer ciertos aspectos de configuración en la máquina base antes de convertirla en plantilla:

*   **Instalación del Paquete:** La VM debe tener instalado `cloud-init`.
*   **Unidad Cloud-Init:** Se debe añadir una unidad de CD-ROM de tipo "Cloud-Init" en la sección de hardware (`ide2` suele ser el estándar).
*   **Consola Serial:** Muchas imágenes de nube requieren una **consola serial** configurada para mostrar el proceso de arranque y permitir el acceso de emergencia.
*   **Orden de Arranque:** Es vital configurar el disco principal (SCSI o VirtIO) como la primera opción de arranque para agilizar el inicio.
*   **Conversión:** Una vez configurada, la VM se marca como **Template**, lo que la hace de solo lectura y lista para generar clones vinculados de forma extremadamente rápida.

Un ejemplo para nuestro entorno de laboratorio del flujo de trabajo típico por línea de comandos para crear una plantilla base (ej. Ubuntu) es el siguiente:

1.  **Descargar la imagen:** `wget https://cloud-images.ubuntu.com/.../bionic-server-cloudimg-amd64.img`.
2.  **Crear la VM base:** 
    ```bash
    qm create 9000 --memory 2048 --net0 virtio, \
    bridge=vmbr0 --scsihw virtio-scsi-pci
    ```
3.  **Importar el disco:** 
    ```bash
    qm set 9000 --scsi0 local-lvm:0,import-from=/ruta/a/la/imagen.img
    ```
4.  **Añadir el drive de Cloud-Init:**
    ```bash
    qm set 9000 --ide2 local-lvm:cloudinit
    ```
5.  **Configurar arranque y consola:**
    ```bash
    qm set 9000 --boot order=scsi0
    qm set 9000 --serial0 socket --vga serial0
    ```
6.  **Convertir en plantilla:** `qm template 9000`.

## Aspectos de Configuración Abordables
Una vez creada la plantilla, el administrador puede definir los siguientes parámetros antes de arrancar los clones:

*   **Usuarios y contraseñas:** Se puede definir un usuario específico (`ciuser`) y una contraseña (`cipassword`), aunque por seguridad se prefiere el uso de llaves SSH.
*   **Claves SSH:** Permite inyectar claves públicas (`sshkeys`) para acceder de forma segura sin contraseña.
*   **Credenciales de Red:** Configuración de IP estática o DHCP (`ipconfig[n]`), DNS (`nameserver`) y dominios de búsqueda (`searchdomain`).
*   **Actualizaciones:** Opción de realizar una actualización automática de paquetes en el primer arranque (`ciupgrade`).
*   **Configuraciones personalizadas:** Mediante el uso de "snippets", se pueden pasar archivos de configuración YAML personalizados para tareas más complejas (`cicustom`).

### Ejemplo de despliegue de un clon:
```bash
qm clone 9000 123 --name servidor-web
qm set 123 --sshkey ~/.ssh/id_rsa.pub
qm set 123 --ipconfig0 ip=192.168.1.50/24,gw=192.168.1.1
qm start 123
```

**Importante:** Para que Cloud-Init funcione correctamente, la VM debe tener configurado un dispositivo de visualización de tipo **consola serial**, ya que es un requisito de muchas imágenes de nube para mostrar el proceso de arranque.
