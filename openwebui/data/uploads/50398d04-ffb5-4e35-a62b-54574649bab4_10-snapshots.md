# Práctica: Gestión de Snapshots en Proxmox VE

## Introducción
Un **snapshot** captura el estado de una máquina virtual (VM) en un momento específico, incluyendo su configuración y, opcionalmente, el estado de su memoria RAM. 
**Objetivos:**

*   Aprender a crear snapshots con y sin memoria RAM.
*   Validar la reversión de cambios mediante el proceso de *rollback*.
*   Inspeccionar cómo Proxmox almacena jerárquicamente estas imágenes en el archivo de configuración.

## Snapshot de Línea Base (Base-line)
Como siempre ejecutaremos los comandos de la práctica desde alguno de los nodos del clúster. En este caso accedemos a `pve1`
```bash
vagrant ssh pve1
sudo -i
```

Antes de realizar cambios en el sistema operativo de la máquina virtual (ID 100), crearemos un estado seguro:
```bash
qm snapshot 100 snap-inicial --description "Estado limpio antes de cambios"
```

**Nota técnica:** Este snapshot es "en caliente" pero solo guarda el estado de los discos y la configuración. Si la VM está encendida, se recomienda tener instalado el **QEMU Guest Agent** para asegurar la consistencia del sistema de archivos mediante el comando `fs-freeze` automático que realiza Proxmox.

## Simulación de "Desastre" o Cambio Crítico
Accede a la consola de la VM (ID 100) y realiza una modificación que desees revertir más adelante:

* Crea un archivo de prueba: `touch /root/archivo_importante`.
* Borra un archivo existente: `rm /var/log/lastlog`

## Reversión al Estado Inicial (Rollback)
Para deshacer los cambios realizados en el paso anterior, utilizaremos el comando de retroceso:
```bash
qm rollback 100 snap-inicial
```
**Importante:** Al realizar un rollback a un snapshot que no incluye el estado de la memoria RAM, la máquina virtual se detendrá y se reiniciará para aplicar el estado de los discos del snapshot. Al volver a entrar, el archivo `/root/archivo_importante` habrá desaparecido y dispondremos de nuevo del archivo `/var/log/lastlog`anterior.

## Snapshot con Memoria RAM (vmstate)
Ahora realizaremos un snapshot que guarde exactamente lo que está ocurriendo en la CPU y la RAM. Esto permite volver a un punto donde incluso los programas abiertos siguen ahí.

1.  Ejecutemos un un proceso largo en la VM, en este caso el comando `yes` que envía el mensaje "y" a la salida estándar continuamente. Lo haremos en segundo plano:
```bash
yes > /dev/null &
```
2.  Desde el host Proxmox, ejecuta lo siguiente para crear una snapshot que incluya la RAM:
```bash
qm snapshot 100 snap-con-ram --vmstate 1 \
--description "Incluye memoria de ejecucion"
```
**Requisito:** Para guardar el estado de la RAM, Proxmox requiere un almacenamiento que soporte volúmenes de estado (como ZFS o Ceph) o el uso de formato `qcow2`.
3. A continuación detendremos el proceso, en este caso al ser el único proceso en segundo plano (podemos ver su jobid con el comando `jobs`), lo detendremos con:
`kill %1`
4. Al recuperar la snapshot anterior:
```bash
qm rollback 100 snap-con-ram
```
Veremos, con el comando `jobs` como el proceso, tras la restauración, sigue en memoria.

## Inspección y Limpieza
Es fundamental que el administrador sepa visualizar la jerarquía de snapshots y no acumular demasiados, ya que pueden afectar al rendimiento según el almacenamiento usado. Para **listar snapshots del recurso:**
```bash
qm listsnapshot 100
```
Este comando muestra la relación padre-hijo de las capturas realizadas.

Los snapshots se guardan como secciones de texto dentro del archivo de configuración de la VM. Pueden verse con:
```bash
more /etc/pve/qemu-server/100.conf
```
Observarás etiquetas como `[snap-inicial]` con sus respectivos sellos de tiempo (`snaptime`) y configuraciones de hardware en ese momento.

Podemos **eliminar snapshots obsoletos** y así liberar espacio y consolidar los datos:
```bash
qm delsnapshot 100 snap-con-ram
qm delsnapshot 100 snap-inicial
```

## Cuadro Resumen de Comandos

| Acción | Comando |
| :--- | :--- |
| Crear snapshot (Disco) | `qm snapshot <vmid> <nombre>` |
| Crear snapshot (+RAM) | `qm snapshot <vmid> <nombre> --vmstate 1` |
| Listar jerarquía | `qm listsnapshot <vmid>` |
| Revertir estado | `qm rollback <vmid> <nombre>` |
| Eliminar snapshot | `qm delsnapshot <vmid> <nombre>` |

!!!NOTA
    Si un snapshot se queda "bloqueado" debido a un fallo de red o energía durante su creación, puede usar el comando `qm unlock 100` para liberar el recurso, siempre que esté seguro de que el proceso ya no se está ejecutando.
