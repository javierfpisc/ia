# Práctica: Instalación de Proxmox

## 1. Actualización del sistema e instalación de Proxmox con vagrant y VirtualBox
Actualizamos las MVs del despliegue a la versión 13 de Debian. Para ello, desde el directorio **vagrant**, ejecutamos:
```bash
for node in pve1 pve2 pve3; do
  vagrant ssh $node -c "cat > /tmp/install_proxmox.sh" < install_proxmox9.sh
  vagrant ssh $node -c "chmod a+x /tmp/install_proxmox.sh"
done
```
El bucle anterior copia el script de instalación en cada una de las nodos MVs que serán los nodos del clúster.

A continuación, en cada nodo entramos con vagrant ssh `<nodo>` y ejecutamos:

```bash
sudo -i
bash -c /tmp/install_proxmox.sh
```

!!! info "¡Respuestas al instalador!"
    El instalador hará una serie de preguntas a las cuales contestaremos con la opción por defecto, pulsando INTRO

## 2. Pasos de ejecución del script:
El script de automatización utilizado está diseñado para transformar una instalación base de Debian en un nodo de **Proxmox VE**, configurando el entorno para que la instalación sea desatendida y el sistema se actualice a una versión específica basada en Debian Trixie. A continuación se detallan los pasos ejecutados:

### 1. Preparación del Entorno No Interactivo
El script comienza configurando variables de entorno para que las herramientas de gestión de paquetes no soliciten intervención humana durante la instalación. Esto incluye el modo de reinicio automático para servicios que se actualicen. Además, utiliza `set -e` para asegurar que el script se detenga inmediatamente si ocurre cualquier error durante la ejecución.

### 2. Configuración de Locales e Idioma
Se establece el idioma del sistema y la codificación de caracteres a español (`es_ES.UTF-8`). El script genera los locales necesarios y actualiza la configuración del sistema para que este sea el idioma predeterminado en todas las sesiones.

### 3. Preconfiguración de GRUB
Para evitar interrupciones manuales, el script utiliza `debconf-set-selections` para indicar que el cargador de arranque **GRUB** debe instalarse automáticamente en el disco principal. También se configura para que las librerías se reinicien sin preguntar al usuario.

### 4. Credenciales de Acceso
Se asigna una contraseña estática para el usuario **root** (`abc123.`), garantizando que el administrador tenga acceso inmediato tras la conversión del sistema.

### 5. Actualización de Repositorios (Migración a Trixie)
El script realiza un cambio crítico en la configuración de las fuentes de software, sustituyendo las referencias a Debian *Bookworm* por **Debian Trixie**. Esto prepara el sistema para una base de software más reciente, alineada con las versiones experimentales o futuras de Proxmox. Asimismo, elimina los archivos de repositorios empresariales (`pve-enterprise`) que requieren suscripción de pago.

### 6. Actualización del Sistema y Repositorio Proxmox
Se realiza una actualización completa de todos los paquetes existentes (`full-upgrade`). Posteriormente, se añade el repositorio oficial de **Proxmox VE (no-subscription)** para la versión Trixie y se importa su clave GPG de seguridad para permitir la descarga e instalación de los paquetes oficiales del hipervisor.

### 7. Instalación de Proxmox VE
Se instalan los componentes principales que forman el hipervisor:

* **proxmox-default-kernel:** El núcleo optimizado para virtualización.
* **proxmox-ve:** El metapaquete que contiene toda la plataforma Proxmox.
* **Herramientas adicionales:** Se instalan servicios como `postfix` para la gestión de correos, `open-iscsi` para almacenamiento en red y `chrony` para la sincronización horaria precisa del clúster.

### 8. Limpieza y Optimización
Una vez instalado Proxmox, el script elimina `os-prober` (una práctica recomendada en entornos virtuales para evitar conflictos con particiones de MVs) y realiza una purga de todos los antiguos núcleos de Linux que no son de Proxmox, liberando espacio en la partición de arranque.

### 9. Reinicio Final
Como paso último, el sistema ejecuta un reinicio automático. Esto es necesario para que el servidor arranque con el nuevo **kernel de Proxmox** y todos los servicios de virtualización se activen correctamente.

### 10. Acceso
Podemos acceder por ssh a los nodos del cluster, o bien utilizar la interfaz de gestión web corriendo en cada nodo en el puerto tcp/8806.
Por ejemplo, para acceder al cluster a través de la interfaz web (pveproxy) de pve1 utilizamos la siguiente URL:

[https://192.168.56.11:8006](https://192.168.56.11:8006)

!!! info "¡Usuario de acceso!"
    Las credenciales de acceso serán para el proveedor de autenticación local **PAM** las mismas que para las cuentas locales, entramos con:

    * usuario: **root**
    * password: **abc123.**
